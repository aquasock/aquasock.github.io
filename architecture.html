System anatomy

A small console.
A clean boundary.

TinyTang splits durable console responsibilities from machine-specific logic. That boundary lets one physical device become many different systems.

BL616 ↔ GW5AST
UART + STORAGE
INPUT / CONTENT SD card + controllers cartridges · media · input
FILES + EVENTS
BL616 TinyTang shell desktop · loader · storage · diagnostics
CONTROL + PAYLOAD
GW5AST-138 Selected FPGA core AE350 · memory · video · audio · custom logic
PIXELS + SOUND
OUTPUT HDMI + audio the system becomes visible

Boot sequence

From card to core.

The shell discovers a cartridge, programs the FPGA, transfers its runtime and content, then hands the experience to the selected system.

  1. 01

    Discover

    Scan storage and recognize the cartridge layout.

  2. 02

    Program

    Load the system bitstream into the FPGA fabric.

  3. 03

    Transfer

    Send runtime and media payloads across the console boundary.

  4. 04

    Run

    Route controls and let the selected machine take over.

Design principles

What stays constant.

Ⅰ

Shared shell

Common UX and device services belong in TinyTang instead of being reinvented by every system.

Ⅱ

Owned interfaces

Each project documents and tests the boundary it actually controls.

Ⅲ

Hardware proof

Simulation helps, but behavior on the Tang Console is the final measure.

Ⅳ

Open path

The stack aims to remain inspectable from application code down to the generated bitstream.
