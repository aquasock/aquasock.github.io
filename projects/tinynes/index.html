A complete console path

Not just an emulator.
A machine around it.

TinyNES runs a tuned FCEUmm core on the FPGA’s 750 MHz AE350 RISC-V CPU. Purpose-built FPGA logic supplies memory, HDMI video, audio, controller buses, and the live TinyDesk overlay.

Play a cartridge

From library
to game.

Once TinyNES is installed, games launch entirely from TinyDesk. No host computer or shell is needed during normal play.

  1. 01

    Add your games

    Place legally obtained .nes files—or ZIP files containing one NES image—under /root/media/nes on the console’s card.

  2. 02

    Open TinyNES

    Launch the TinyNES window from TinyDesk and browse the Library tab. Folders are supported.

  3. 03

    Select and launch

    Choose a cartridge. TinyTang loads the FPGA core, player, and game in roughly ten seconds.

  4. 04

    Return safely

    Hold HOME + − to finish the session and return to the desktop core.

Bring your own cartridges.

TinyNES does not distribute commercial game images. The repository, build outputs, and console card keep user-owned ROM data separate.

The experience

Video, sound,
and a desktop.

The emulator produces the NES picture and sound. Dedicated hardware carries them to the display and speakers while the console shell remains one button away.

V / 01

Three picture modes

The 256×240 NES image is centered in a 1280×720 HDMI frame. Choose authentic 8:7 pixels, square 1:1 pixels, or a 4:3 television frame.

8:71:14:3
A / 02

One audio stream

Game audio plays through HDMI and the optional Digilent Pmod I2S2. TinyDesk provides one logarithmic master volume and mute for both outputs.

UI / 03

TinyDesk stays live

Tap HOME and the 80×45-cell TinyDesk layer replaces the game picture. The game keeps running underneath—with sound—while controller input moves to the desktop. Tap HOME again to return.

Persistent play

Stop now.
Continue later.

Each cartridge gets one persistent save-state slot. Saving is immediate in SDRAM, then TinyTang writes the state to the card in the background and verifies it before replacing the previous copy.

  • States are matched to the cartridge CRC
  • Battery-backed game RAM is retained
  • The Saves tab exposes file, size, core, and frame details
  • Interrupted writes leave the previous state intact
